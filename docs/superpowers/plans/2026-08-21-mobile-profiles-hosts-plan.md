# Mobile: profiles and the SSH host list — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mobile displays the user's session profiles and SSH host list, and can ask a chosen desktop to open a session with a chosen profile.

**Architecture:** Two TypeScript envelope readers over primitives `opaque.ts` already has, pinned by golden vectors the Go code generates; plus a new request/response frame pair routed by `host_id` (not `session_id`) so a create request can reach a desktop that has no sessions yet.

**Tech Stack:** Go 1.23.12, Wails v2.12.0, Vue 3, Vitest, Capacitor.

**Spec:** `docs/superpowers/specs/2026-08-21-mobile-profiles-hosts-design.md`

## Global Constraints

- **Redline #4:** do not change the payload structure of any EXISTING frame. This item adds two new types (`0x3b`, `0x3c`); nothing existing may be touched.
- **Redline #5:** `internal/` must not import `desktop/`.
- **Redline #2:** do not touch `SetSubscriberLifecycle` or the uplink subscriber count. A create request is not a subscription.
- Go: pinned toolchain **go1.23.12**. Node: **20**. `gofmt -l $(git ls-files '*.go')` must be empty — CI gates it.
- Any change under `desktop/frontend/src` or `web/src` requires rebuilding `internal/relay/web-dist/` via `./scripts/build-web.sh`.
- i18n parity is compile-enforced by `satisfies Messages` in `zh-CN.ts`.
- **iOS bundles `desktop/frontend`, not `web/src`.** Mobile-only code lives in `desktop/frontend/src/platform/capacitor.ts` and its neighbours. Anything desktop-only must be gated on `platform.caps.wailsBindings` with a test mounting both shapes — items 29, 30 and 31 each needed a fix round for that omission.

### Task 1: The two envelope readers, pinned by Go-generated vectors

**Files:**
- Create: `desktop/frontend/src/lib/syncedBlobs.ts` + `syncedBlobs.test.ts`
- Create: `desktop/testdata/synced_blob_vectors_test.go` (or extend an existing test) that WRITES the fixture
- Create: the committed fixture itself

**Interfaces:**
```ts
export function openProfilesBlob(accountKey: Uint8Array, value: string): { profiles: ProfileView[]; defaultProfileId: string }
export function openSSHHostsBlob(accountKey: Uint8Array, value: string): { hosts: SSHHostView[]; keys: SSHKeyView[] }
```

**What the Go side actually does — read it, do not trust this summary:** `sealProfiles` (`desktop/profiles.go:88`) and `sealSSHHosts` (`desktop/ssh_sync.go:36`). The value is a JSON string of base64 of `SealUnsequenced(DeriveSessionKey(accountKey, <fixed UUID>), <fixed UUID>, <AAD tag>, json(payload))`. The fixed UUIDs are `profilesSyncSessionID` (`profiles.go:18`) and its `ssh_sync.go` counterpart; the AAD tags are `e2eecrypto.AADTag*`.

**Behaviour the tests must pin:**
- A fixture GENERATED BY GO opens to the expected contents. The Go test must WRITE the fixture, not assert against a hand-written one — a hand-written fixture encodes what someone believed the format was.
- Changing the Go envelope makes the TS test fail. Demonstrate this: mutate the AAD tag on the Go side, regenerate, and show the TS test failing.
- `SSHHostView`/`SSHKeyView` expose NO credential field. The sealed blob contains `sshCredential` and `sshKeySecret` maps; the reader must not surface them. Assert on the decoded object's keys.
- A profile with `SyncEnv: false` arrives with no `Env` (Go stripped it before sealing) — the view must distinguish that from "no env vars set".
- A wrong account key fails cleanly rather than returning garbage.

- [ ] Steps: failing tests → generate the fixture from Go → implement → run → mutation check (AAD tag change; credential field surfaced) → commit.

### Task 3: The frame pair

**Files:**
- Modify: `internal/proto/frame.go` (+ codec if the payloads need one)
- Test: `internal/proto/frame_test.go`

**Interfaces:**
```go
TypeSessionCreate  Type = 0x3b
TypeSessionCreated Type = 0x3c

type SessionCreatePayload struct {
    RequestID string `json:"request_id"`
    HostID    string `json:"host_id"`
    ProfileID string `json:"profile_id"`
}
type SessionCreatedPayload struct {
    RequestID string `json:"request_id"`
    OK        bool   `json:"ok"`
    SessionID string `json:"session_id,omitempty"`
    Error     string `json:"error,omitempty"`
}
```

**Behaviour the tests must pin:**
- Round-trip encode/decode.
- **No existing frame's payload changed.** Add a test that fails if any existing type constant's value moves, and confirm `0x3b`/`0x3c` were previously unused.
- An older peer receiving an unknown type ignores it rather than erroring — verify that is the existing behaviour and keep it.

### Task 4: Relay routing, by host

**Files:**
- Modify: `internal/relay/client_conn.go`, `internal/relay/uplink_conn.go`, plus a router
- Test: alongside

**Behaviour the tests must pin:**
- A `TypeSessionCreate` is routed to the uplink that announced its `host_id`, and to no other.
- The response goes to the REQUESTING CLIENT ONLY, never broadcast — the same rule `fs_router.go` enforces and for the same reason.
- A request naming an unknown/disconnected `host_id` gets a prompt error, not silence.
- A client not authenticated for that uplink's owner is refused. Write the test that proves a *different user's* client cannot reach the host.
- The relay never inspects anything beyond the routing head. It holds no key.
- Requests expire (mirror `fsRequestTTL`'s lazy same-lock sweep, which makes a response-vs-reap race structurally impossible).

### Task 5: The desktop handler

**Files:**
- Modify: `desktop/uplink.go` (dispatch), plus a handler file
- Test: alongside

**Behaviour the tests must pin:**
- The profile is resolved from LOCAL config by ID. A body is never accepted — assert that a payload carrying profile fields cannot influence the created session.

- One in-flight create per requesting client.
- The created session is announced as usual, so the phone's existing attach path finds it.
