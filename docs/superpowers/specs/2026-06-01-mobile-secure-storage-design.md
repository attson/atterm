# Mobile secure token storage (design)

Date: 2026-06-01
Status: Draft (design phase); pending implementation plan
Roadmap item: P1.9

## 1. Goal

Move the mobile app's relay credentials (`atterm.relay` JSON blob —
contains the `atk_…` API token) out of localStorage and into iOS
Keychain so a backup, jailbreak, or browser-data leak doesn't expose
the token. Migrate existing localStorage values on first read after
upgrade, then clear them. Add UI warnings so users who enable
"Allow insecure HTTP" understand what that entails.

After this lands:

- iOS users' relay credentials live in Keychain with
  `kSecAttrAccessibleAfterFirstUnlock`.
- Users upgrading from an earlier version transparently migrate on
  their next app open: the existing localStorage blob is read, written
  to Keychain, then removed from localStorage.
- The "Allow insecure HTTP" checkbox gets a clearer warning label and
  a persistent in-app banner when the active session is HTTP.

Out of scope:

- Android Keystore (no Android project exists yet; revisit when
  `cap add android` lands).
- Per-field encryption inside Keychain (the whole `RelayConfig` JSON
  goes in as one secret — its non-token fields are cheap metadata, not
  worth the extra plumbing).
- Tightening `NSAppTransportSecurity` (`NSAllowsArbitraryLoads`
  stays `true` — explicitly user-elected; the deterrent moves to UI).
- Biometric prompt on read (`AccessibleAfterFirstUnlock` is the right
  trade-off for a background-reconnecting terminal app).
- Web (PWA) browser users — they continue using localStorage. Browsers
  don't have a Keychain analogue we can safely depend on.
- Wails desktop users — already use a separate config-file backend
  (`appConfig`); not affected.

The TS shim lives at the platform layer (one file). Capacitor's
`registerPlugin` returns a typed proxy; if the native plugin is
absent (e.g., running in vitest / on web), the shim falls back to a
sync in-memory implementation so tests don't touch real Keychain.

## 3. Storage contract

### 3.1 Keychain shape

Single keychain item per app install:

| Attribute | Value |
|---|---|
| `kSecClass` | `kSecClassGenericPassword` |
| `kSecAttrService` | `"com.attson.atterm"` |
| `kSecAttrAccount` | `"atterm.relay"` |
| `kSecAttrAccessible` | `kSecAttrAccessibleAfterFirstUnlock` |
| `kSecValueData` | UTF-8-encoded JSON of `RelayConfig` |

`AccessibleAfterFirstUnlock` (not `WhenUnlocked`) keeps reconnection
working when the phone is locked but already unlocked once since
boot — critical for "open the app from a notification" UX without
prompting for a passcode.

### 3.2 TS shim — `platform/secureStorage.ts`

```ts
export interface SecureStorage {
  set(key: string, value: string): Promise<void>
  get(key: string): Promise<string | null>
  remove(key: string): Promise<void>
}

// secureStorage is the production-or-fake instance; choice is fixed
// at module-load time based on whether the native plugin is present.
export const secureStorage: SecureStorage = /* see §3.3 */
```

### 3.3 Native plugin presence detection

`Capacitor.registerPlugin<AttermSecureStoragePlugin>('AttermSecureStorage')`
always returns a proxy. The TS shim probes once with a no-throw call:

```ts
async function detectNative(): Promise<boolean> {
  try {
    await native.get({ key: '__probe__' })
    return true
  } catch (e: any) {
    return e?.code !== 'PLUGIN_NOT_AVAILABLE'
  }
}
```

If detection succeeds → use native. Otherwise → in-memory `Map`
backed by a closure (test mode). Web browsers and vitest both fall
into the in-memory path. The detection result is cached in a
module-level promise so we probe at most once.

### 3.4 Native plugin — `AttermSecureStorage`

iOS / Swift implementation. Single file under
`mobile/ios/App/App/Plugins/AttermSecureStorage/AttermSecureStoragePlugin.swift`.
Exposes three methods over Capacitor's bridge:

- `set({ key, value })` → `SecItemAdd` with `kSecValueData`. If item
  already exists (`errSecDuplicateItem`), retry with `SecItemUpdate`.
- `get({ key })` → `SecItemCopyMatching` with `kSecMatchLimit = One`,
  `kSecReturnData = true`. Returns `{ value: <string> }` on hit or
  `{ value: null }` on `errSecItemNotFound`.
- `remove({ key })` → `SecItemDelete`. Treats `errSecItemNotFound` as
  success.

Any other `OSStatus` is wrapped in `CAPPluginCall.reject` with code
`KEYCHAIN_ERROR` and the `OSStatus` integer in the message.

The plugin is registered in `AppDelegate.swift` (or by Capacitor's
auto-discovery via the `@objc(...)` annotations on the plugin class
— preferred, no `AppDelegate` change).

## 4. Migration flow

```
┌──────────────────────────────┐
│ capacitor.ts relay.load()    │
└──────────────────┬───────────┘
                   │
                   ▼
   ┌────────────────────────────┐
   │ secureStorage.get("relay") │
   └─────────────┬──────────────┘
                 │ found?
        ┌────────┴────────┐
       yes              no
        │                │
        ▼                ▼
   return parsed   ┌──────────────────────────────┐
   RelayConfig    │ localStorage["atterm.relay"]? │
                  └─────────────┬────────────────┘
                                │ found?
                       ┌────────┴────────┐
                      yes              no
                       │                │
                       ▼                ▼
              ┌─────────────────────┐  return null
              │ secureStorage.set() │
              │ localStorage.remove │
              │ return parsed       │
              └─────────────────────┘
```

`relay.save()` always writes to `secureStorage` only.
`relay.clear()` removes from `secureStorage` AND `localStorage`
(belt-and-braces in case migration was interrupted between the two
writes).

A single migration attempt per app load — the "promote from
localStorage" branch only runs inside `load()`, never in `save()`.

## 5. UI changes

### 5.1 `MobileSetup.vue`

The "Allow insecure" checkbox grows a warning text block beneath it:

```
☐ Allow insecure HTTP relay (no TLS)
  ⚠ Your API token will be sent in cleartext over Wi-Fi.
    Only enable for local-network testing.
```

The warning is always visible (not just when checked) so the user
sees the consequence before opting in. Hidden behind an `<aside>`
with `data-state="warn"` styling (yellow left-border, matches the
relay health page warning style).

### 5.2 `InsecureBanner.vue` (new)

A 1-line banner at the very top of the mobile app's main view (just
below the safe-area inset), shown whenever the active relay URL
starts with `http://`. Tappable to expand:

```
┌─────────────────────────────────────┐
│ ⚠ Insecure relay (HTTP)             │  ← always visible while http
└─────────────────────────────────────┘
       ↓ tap
┌─────────────────────────────────────┐
│ ⚠ Insecure relay (HTTP)             │
│   API tokens and terminal output    │
│   are transmitted unencrypted. Use  │
│   HTTPS in production.              │
│                  [ Dismiss ]        │
└─────────────────────────────────────┘
```

Dismiss state is per-session (in-memory ref), not persisted — the
banner returns on every app launch so the warning isn't trained
away.

### 5.3 i18n keys (en + zh-CN)

New under `mobile.insecure`:

- `warning.title`
- `warning.body`
- `warning.dismiss`
- `setupHint` (the always-visible block under the checkbox)

## 6. Errors and observability

- Keychain errors during `set` are surfaced to the UI: the existing
  "Pairing failed" / "Couldn't reach relay" toast layer gets a new
  code `secure_storage_unavailable`. Without secure storage, the app
  cannot continue — log to console and prompt the user to relaunch.
- Migration partial failure (Keychain write succeeded but
  localStorage clear failed) is non-fatal: the next launch will read
  from Keychain, the localStorage value remains until the next
  successful `clear()`. Acceptable.
- The plugin doesn't log token contents anywhere; OSLog calls (if
  any) are restricted to the error path with `OSStatus` only.

## 7. Testing

### 7.1 `platform/__tests__/secureStorage.test.ts`

- `set` + `get` round-trip via the in-memory backend
- `get` for missing key → `null`
- `remove` + `get` → `null`
- `set` twice with different values → second value persists (upsert)

### 7.2 `platform/__tests__/capacitor.test.ts` (extended)

- **Migration** — seed localStorage with a valid `atterm.relay` JSON,
  call `relay.load()` → assert: returned value matches, `secureStorage.get`
  now returns it, `localStorage["atterm.relay"]` is `null`.
- **Priority** — seed both stores with different JSON, call `load()` →
  assert: Keychain value wins, localStorage value is left alone.
- **No-migration path** — seed only Keychain, call `load()` →
  assert: returned value, localStorage untouched.
- **Empty path** — both stores empty → `load()` returns `null`.
- **`save` writes only to Keychain** — assert `localStorage.setItem`
  is never called.
- **`clear` wipes both** — pre-seed both, call `clear()`, assert both
  stores empty.

### 7.3 Component tests

- `InsecureBanner.vue` — renders only when prop `relay_url` starts
  with `http://`; expands on tap; emits `dismiss`.
- `MobileSetup.vue` — the always-visible insecure-warning block
  exists in the DOM regardless of `allowInsecure` value.

### 7.4 Manual / smoke (not gated)

- Build the iOS bundle (`cap sync ios` then Xcode build) and run on
  the simulator: enter relay URL + token via the manual form, kill
  the app, relaunch — credentials are restored, localStorage stays
  empty. Roll back to a v0.3 build, enter credentials (which write
  to localStorage), upgrade to the v0.4 build, confirm migration on
  first relaunch.

## 8. Rollout

- The new plugin and TS shim ship together. No feature flag.
- Existing v0.3 users transparently migrate on their next app launch.
- No backend changes; no relay-side support needed.
- README does not need an update — the migration is silent and the
  user-visible UI change is the strengthened insecure warning, which
  is self-explanatory.

## 9. Non-goals revisited

- Android: parking until the project adds an Android project. The
  TS shim's plugin-detection design means swapping in an Android
  Keystore plugin later requires no JS-side changes — just an
  Android Kotlin file mirroring the iOS plugin's contract.
- Hardware Secure Enclave: `kSecAttrTokenID = kSecAttrTokenIDSecureEnclave`
  could harden further, but Secure Enclave only stores keys, not
  arbitrary blobs — we'd need to wrap the JSON with an SE-protected
  symmetric key. Disproportionate complexity for a single-user app's
  threat model.
- "Sign in with Apple" / biometric prompt on read: out of scope; the
  `AfterFirstUnlock` accessibility tier is what existing mobile
  banking apps use for similar background-reconnect needs.
