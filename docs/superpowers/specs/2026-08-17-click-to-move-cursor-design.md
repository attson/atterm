# 提示符内点击移动光标（P5 第 23 项）— design

Date: 2026-08-17
Status: Drafted — awaiting user review before plan.
Parent: [2026-08-16 sync-layer roadmap](./2026-08-16-sync-layer-roadmap-design.md) §5 P5 第 23 项 · roadmap 第 23 项

## 0. Summary

在 shell 提示符的输入行里点一下，光标移到点击处——像普通文本框那样，而不是按住方向键挪。

实现方式是终端算出点击列与当前光标列的差，发对应数量的 ← / → 键给 PTY。**没有更直接的办法**：终端无法直接设置 shell 行编辑器的光标，只能用 shell 自己也认的按键。

## 1. 母 spec 的一处事实错误

roadmap 第 23 项写着：

> `internal/session/applyOSC133Locked` 已有完整 OSC 133 解析，此项只需前端补 click → 光标位移

**前半句与本项无关。** 那份解析在 Go 侧的 `internal/session`，服务的是 task_state / 命令摘要，前端够不着它，也不会因为它存在而少写一行。

但结论歪打正着：`TerminalView.vue:1710` **已经**注册了 `term.parser.registerOscHandler(133, …)`（当前用于命令完成通知），并且返回 `false` 不消费序列。那才是本项该挂的地方。所以「只需前端补」成立，理由不同。

顺带确认了一件让这条路走得通的事：Go 侧的 `consumeOSC133Locked` 在**副本**上工作，不从流里剥离 OSC 133——所以这些序列确实抵达 xterm，前端能自己追踪提示符边界。

## 2. Goals

- 在**已知安全**的前提下，点击提示符输入行把光标移到点击列。
- 不安全时**什么都不做**，而不是猜。
- 不干扰现有的选区、链接点击、右键菜单、移动端触摸路径。

## 3. Non-Goals

- 不做多行输入（续行、多行编辑器）的点击定位。方向键在多行里的语义由 shell 决定，终端无从判断。
- 不做垂直移动（点击其它行）。同上，且更危险。
- 不做「对未声明支持的 shell 也试一把」的开关。理由见 §5。
- 不动 Go 侧的 OSC 133 解析。

## 4. 机制

xterm 的 `term.buffer.active.cursorX/cursorY` 给当前光标位置；点击位置由 `term.element` 的坐标除以 cell 尺寸得出（仓库已有 `predictCellDims` 与链接命中所需的坐标换算，复用）。

差值 `delta = clickX - cursorX`，向 PTY 发 `|delta|` 个 `\x1b[C`（右）或 `\x1b[D`（左）。走既有的 `sendInput` 路径。

**发送必须一次成帧、不要逐键 setTimeout**：红线 #28 那条教训是关于 CR 被当 paste，跟这里不同；这里的风险是 N 次独立 IN 帧在 relay 往返下乱序或被节流。拼成一个字符串一次发。

## 5. 安全门控——本设计的全部难点

发方向键给一个不期待方向键的程序，后果从「输入被改坏」到「在 TUI 里触发导航」。所以只有全部条件成立才动作：

1. **不在 alt-screen**（`vim` / `htop` / AI CLI 全屏 UI 都在这里）。
2. **处于提示符与命令之间**——OSC 133 收到 `B` 之后、`C` 之前。跑命令时点击不能发键。
3. **点击行 == 光标行**。跨行不做（§3）。
4. **本 pane 是 driver**。viewer 的 `disableStdin` 会挡住输入，但不该先发出去再被丢。
5. **shell 声明了 `cl=line`**（OSC 133 的 Semantic Prompt 扩展，意为「我的提示符输入是单行，方向键在其中安全」）。

### 5.1 第 5 条的代价要说清楚

`cl=line` 目前只有 **fish 4.1+ 与 nushell 0.111+** 默认声明。**zsh 和 bash 不声明**——也就是说这个功能对本项目多数用户（包括默认 shell 是 zsh 的场景）**什么都不会发生**。

这是有意的，不是遗漏：那条声明正是 shell 在说「我的行编辑器就是单行，你发方向键是安全的」。没有声明就假设安全，等于拿用户正在编辑的命令行赌一个我们无从验证的前提——而赌输的形态是「命令被悄悄改成别的」，可能直到回车之后才发现。

不做逃生开关（§3），因为一个默认关、说明文案必须解释「可能弄坏你的输入」的设置，价值低于它的解释成本。若将来 zsh 支持了，这个功能自动开始工作，无需改代码。

## 6. 集成风险：同一个组件里已有五个指针处理器

本项真正的风险不在跨进程，而在 `TerminalView.vue` 内部。已有的捕获阶段处理器：

| 处理器 | 用途 |
|---|---|
| `onTermPointerDown` / `onTermMouseDown` / `onTermTouchStart` | 移动端防误触、软键盘折叠态下拦截重新聚焦 |
| `onTerminalMouseUp` | mod+click 打开链接（`shouldActivateLink` 判定；普通点击留给选区） |
| `openContextMenu` | 右键菜单 |

外加 xterm 自己的选区处理与 `useTerminalLinkProvider`。

所以新增的点击判定必须额外满足：

- **不是拖拽**——mouseup 位置与 mousedown 位置一致。仓库已有 `linkClickDownPos` 在做这件事，复用它而不是再记一份。
- **没有活动选区**——点击结束选区时不该顺带移光标。
- **不是链接激活**——`onTerminalMouseUp` 已经在 mod+click 时 `stopImmediatePropagation`，顺序上要在它之后判定。
- **不是触摸**——移动端的点击语义由既有的防误触逻辑管，本项只处理鼠标。

## 7. 风险

1. **cell 尺寸换算漂移**：字号/行高现在可配（第 20 项），点击列的换算必须用当前实际 cell 尺寸，不能用常量。
2. **光标位置读取时机**：`buffer.active.cursorX` 在 xterm 处理完写入队列后才准。点击发生在用户交互线程，通常安全；但若刚好有大量输出在写入，读到的可能是旧值——多发或少发几个方向键。缓解：门控第 2 条（必须在提示符与命令之间）本身就排除了输出繁忙的情形。
3. **宽字符**：CJK 占两列。按列算 delta 时，shell 的方向键按**字符**移动而非按列。含 CJK 的命令行会移错位置。缓解：读该行的实际单元格，按字符边界折算，而不是拿列差直接当次数。**这一条是本项最容易写错的地方，必须有测试。**

## 8. 验证

- `cl=line` 门控：声明了才动作；未声明时点击不产生任何 IN 帧。
- alt-screen、非提示符期、跨行、viewer、拖拽、有选区——各一条，断言不发送。
- 宽字符折算：一行含 CJK 时，点击某字符后光标落在该字符而不是偏移若干列（§7.3）。
- 手动：fish 4.1+ 下点击生效；zsh 下点击无反应且无副作用；`vim` 里点击不发方向键。

## 9. 与母 spec 的差异

- 母 spec 称本项可复用 `applyOSC133Locked`；实际不能（§1）。结论不变，理由不同。
- 母 spec 未提 `cl=line` 的覆盖面。本设计明确：**zsh / bash 下本功能不生效**，这是安全门控的直接后果，应在 roadmap 勾选时如实标注，而不是记成「已完成」让人以为处处可用。
